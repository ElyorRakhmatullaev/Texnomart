## 2026-06-11 — Texnomart Promo: S4 — Управление изменениями (Phase 2: изменение после согласования + повторное согласование маркетинга + инкрементальная отправка)

Versions are now lifted into page state (`liveVersions` Map; `versionsFor` overrides the seed once a correction is sent) — so the drawer's «История версий»/«Только изменения» reflect the new version immediately. **Period change (§11.5)**: КД «Изменить период» (band button, approved planned campaigns) opens a small date dialog; on apply the period renders **bold + ✏️** and is tracked as a re-approval-requiring change. **VersionHistoryDrawer** gained a **«Черновик — не отправлено»** section atop «Только изменения» (the live un-sent diff) + the re-approval status/action footer (additive optional props; the S3 approvals usage and the Phase-1 «Создать корректировку» hint path are unchanged). `promo-mock-data.ts`: `APPROVED_CAMPAIGN_STATUS`/`isApprovedCampaign`, `diffCampaignChanges` (+`CampaignChangeSet`), `buildSentVersion`, `PromoCampaign.periodChanged`, and 2 seed lines for the now-reachable approved PR-2026-003 (1+1, km-4). `FullCalendarPage`: baseline/baselinePeriods/liveVersions/marketingReapproved state + `changeSetFor`/`reapprovalStateFor`/`versionsFor` + the period dialog (`PeriodEditDialog`) and re-approve/send handlers; `FullCalendarGrid`: changed-cell highlight, `ChangeBadge`, period bold/✏️, «Изменить период» (КД-gated via prop).
