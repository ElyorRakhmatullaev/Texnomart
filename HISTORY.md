## 2026-06-10 — Texnomart Promo: Full promo-calendar layout polish (full-bleed + denser toolbar)
Tightened the `/full-calendar` layout per design feedback: the page now uses the **full main width** (Promo `AppShell` passes `maxWidth="100%"` for `/full-calendar` via `useLocation`, dropping the 1400px cap; other Promo routes keep the centered default), the **column-group chooser moved into the FilterBar row** (rendered as a FilterBar child, `h-9`→`h-8` to match the filter selects), the **FilterBar gray box/horizontal padding is removed on this screen** so the header, filters, and grid all align flush-left, and the **fixed bottom action bar is full-bleed** (breaks past `<main>`'s padding) with `sm:h-14` so its height matches the sidebar's «Свернуть» collapse-button block. Shared change (additive, backward-compatible): `@texnomart/shared` **FilterBar** gained an optional `className` prop (merged via `cn`) to override its container — Dashboard's usages are unchanged (default keeps the gray box + `px-3`). Verified: `build:promo` + `build:dashboard` pass; browser check at 1440px confirmed wrapper `max-width:100%`, header/filter-row/grid all at left 272 (flush), action bar spanning the full main width at 56px (≈ the 57px sidebar block), and «Колонки» inside the filter row. **Follow-ups (same day):** (1) the page **title was clipped** — the shared `PageHeader` forced a fixed `sm:h-14` (56px) too short for the 32px title + subtitle + `pt-3 pb-6`, so with `items-center` it overflowed above the container and got cut at the scroll edge → changed to **`sm:min-h-14`** (grows to fit; backward-compatible — shorter headers still render at 56px, Dashboard unaffected). (2) **Consistent bottom padding across Promo pages**: the `<main>` scroll container's `padding-bottom` is swallowed by the `h-full` content wrapper for any overflowing block-flow page (content overflows the fixed-height wrapper, so main's pb sits mid-scroll), leaving the last card flush against the bottom. Standardized by adding **`pb-6`** to the Promo block-flow page roots (`ShortCalendarPage`, `ShortCalendarDetailPage`, `ModulePlaceholder`) for a uniform 24px bottom gap (verified 24px on the short-calendar list + detail); `/full-calendar` is app-like and intentionally bottoms out at its full-bleed fixed action bar. Shared `<main>`/wrapper left untouched to avoid regressing Dashboard's `h-full` app-like pages. (3) **Short-calendar Pattern F row misalignment**: `ShortCalendarTable` used `min-h-[72px]`, so the scrolling pane's rows grew taller than the frozen pane's whenever content wrapped (campaigns with 3–4 category chips, long КМ-name lists) — the two independent panes then desynced. Switched to a **fixed `h-[72px]`** on both panes and clamped the variable cells to fit (Распределение по категориям caps at 2 chips + «+N» with the full list on `title`; ФИО КМ `line-clamp-2`; `overflow-hidden` safety net) — verified all 6 rows render exactly 72px in both panes with 0px top-delta. Same fix the full-calendar grid already uses (`h-14` fixed rows).
