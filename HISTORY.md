## 2026-06-10 — Texnomart Promo: S2 — Полный промо-календарь (Phase 2: inline editing + validation)
Made the full promo-calendar grid editable, replacing the Phase 1 read-only skeleton. Lines are now lifted into a page-level store (`useReducer` over a `Map<lineId, PromoLine>` seeded from `PROMO_LINES`) so edits propagate live to the installment columns, validation, and the action bar. New components under `Promo/src/app/components/full-calendar/`: **EditableCell** — borderless inline input (number/money/percent/text) that commits on blur/Enter, cancels on Esc, sized to the fixed row height so the two Pattern-F panes stay aligned; shows the required «не заполнено» marker when empty, and a ✏️ manual-override pencil (read-only roles see the pencil too); **WarehousePopover** — per-warehouse остаток breakdown + total (§8.2.2, read-only from 1С), opened by a small native-`<button>` trigger beside the editable остаток value (native button so Radix can anchor the popover — the shared `<Button>` can't take a ref under `asChild`). `FullCalendarGrid` now renders КМ-source fields as editable cells (остаток → `stockManual` + ✏️ on manual edit; новая цена → installment block auto-recalcs live), editable «В рекламу» checkboxes, a leading row-select column + per-campaign group select for **bulk «В рекламу»**, and dynamic required markers (Прогноз продаж always; gift fields for gift типы). `FullCalendarPage` owns the store + bulk-select state, shows a live validation summary (invalid-line count), a bulk-apply strip («Отметить»/«Снять»/«Сбросить»), and **functional** «Сохранить черновик» / «Отправить на согласование» (gated by live validity; mock toasts — real workflow is S3). `gridFields.ts`: the three «платёж (старая)» installment columns moved `km`→`calc` (they're derived in render), `giftStock` moved `auto`→`km` (КМ-editable for gift кампаний). `promo-mock-data.ts` gained `isGiftType`, `missingRequiredFields`, and `isLineValid`. **Edit gating** (Appendix D): canEditOwnLines roles (КМ/Старший КМ/Администратор) edit all `km`-source cells; Сотрудник маркетинга edits only «В рекламу (выбрано маркетингом)»; КД/ОД stay read-only. Known mock gap: there's no per-person КМ identity, so any КМ-role user edits all КМ lines (same simplification as S1). Verified: `build:promo` passes; browser smoke test confirmed forecast edit clears the red marker & enables submit, warehouse popover anchored in-viewport, bulk-select strip (КМ vs marketing labels), marketing role limited to its one checkbox with disabled save/submit, no new console errors. Phases 3–5 (nomenclature entry + duplicate dialog, Excel import, full 1С availability flow, unplanned creation, mobile per-line Sheet) remain deferred.

## 2026-06-09 — Texnomart Promo: S2 — Полный промо-календарь (Phase 1: grid skeleton)
Built the read-only grid skeleton for the full promo calendar at `/full-calendar`, replacing the placeholder (this is the first of a planned 5-phase build for S2, the most complex screen in the pack). New components under `Promo/src/app/components/full-calendar/`: **FullCalendarGrid** — Pattern F split-pane (frozen **№ промо / ФИО КМ / Номенклатура** pane + horizontally-scrolling block, fixed row heights to keep panes aligned), campaign group bands (план/внеплан badge, тип, название, период), all 38 Appendix-C fields rendered read-only with lock icons on auto/1С/calc sources, required asterisk + «не заполнено» marker on «Прогноз продаж», «дубль»/rejected (tinted row + comment tooltip)/«ожидает 1С» markers; **gridFields.ts** — the 38-field column dictionary (group, width, source→lock, required) with default-visible groups Товар/Цены/Маркетинг; **ColumnGroupToggle** — a «Колонки N из 5» popover with per-group checkboxes (Идентификация/Товар/Цены/Рассрочка/Маркетинг); **FullCalendarPage** — role-gated shell (закуп/аналитика/Дир. маркетинга → «Нет доступа» via `getFullCalendarAccess`, Appendix D), PageHeader, FilterBar (тип/статус/КМ/признак), and a flex-column fixed-footer action bar with a live validation summary (inert in Phase 1 — toasts). `promo-mock-data.ts` gained the `PromoLine` model + 9 seed lines covering every state (normal, missing-required, rejected, duplicate, pending-1С, gift, unplanned), `getWarehouseBreakdown`, `programMonthly`/`installmentTerm` calc helpers (illustrative monthly-payment model), `getPromoLines`/`getCampaignsWithLines`/`getNomenclatureItem`, and `getFullCalendarAccess`. Route wired in `routes.tsx`. **UX fix**: the column-group control was first a segmented ToggleGroup, but the primitive's base `flex-1 min-w-0` squeezed items to equal width and overflowed the longer labels → switched to the checkbox popover; the popover trigger uses a native `<button>` + `buttonVariants` (not the shared `<Button>`, which can't take a ref under Radix `asChild` — that was rendering the popover off-screen). Verified: `build:promo` passes; browser smoke test confirmed grid render (15 default cols, horizontal scroll), column toggle (15→30 cols on Рассрочка), role-gate «Нет доступа», popover anchored in-viewport, no new console errors. Phases 2–5 (inline editing, nomenclature entry, Excel import, 1С states, unplanned creation, mobile per-line Sheet) deferred to follow-on tasks.
