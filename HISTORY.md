## 2026-06-30 — Texnomart Promo: раунд фидбэка #3 — под-проект B (тёмная тема)
Made the dark theme **work end-to-end** — the third of the four 3rd-round sub-projects (after #0+A and C; only **D** матрица прав remains). Before this, a `.dark` toggle and stock shadcn `.dark` CSS variables existed but the theme was non-functional: it wasn't applied on load (reverted on reload), the header and Settings toggles were out of sync, ~270 hardcoded light colors across 49 screen files ignored `.dark`, and the stock `.dark` palette overrode the brand yellow with near-white. **Scope: all Promo screens; hybrid migration (semantic tokens for surfaces + `dark:` variants for bespoke tints); Promo-local persistence + an additive shared-AppShell prop (Dashboard untouched).**

**Infrastructure.** New `Promo/src/app/theme-context.tsx` — `ThemeProvider`/`useTheme` owning `"light"|"dark"|"system"`, persisting `promo:pref-theme`, applying the `.dark` class, and live-listening to the OS `prefers-color-scheme` while in «Системная». An **inline boot script** in `index.html` applies the saved theme **before React paints** (no flash-of-light on reload/deep-link). `App.tsx` wraps the tree in `<ThemeProvider>` and renders a theme-aware `<Toaster theme={theme}>` (sonner). `SettingsPage` now drives the toggle through `useTheme()`.

**Palette (`styles/theme.css`).** Rewrote the `.dark` block as a **layered neutral scale** (`--background` darkest = main area; `--card`/`--popover`/`--sidebar` a step lighter so cards read against it — the inverse of light's white-cards-on-gray-50), **kept the brand `--primary: #FFD60A` / `--primary-foreground: #000000`** (never shadcn's near-white primary), and added `.dark` `--status-*` overrides (same hues, lifted for contrast). Active sidebar item renders brand-yellow in dark via `--sidebar-primary`.

**Shared (`@texnomart/shared`, additive — `build:dashboard` green).** New optional `ThemeController` type + an optional controlled `theme` prop on `AppShell`: when provided (Promo passes `{ value, onCycle }` from `useTheme`), the header toggle reflects/persists via the provider so **header ↔ Settings share one source of truth**; when omitted (Dashboard), the shell keeps its previous self-contained local toggle. Added `dark:` variants to the pattern components Promo renders (page-header, filter-bar, info-row, mobile-list-card, timeline, detail-page-hero, list-page-header, document-thumbnail, status-badge fallback) — light mode byte-identical. Discovered the shadcn `Badge` hover bg is gated on `[a&]:hover` (anchors only), so the `<span>` `StatusBadge`'s `hover:${style.bg}` was a no-op — dropped it so config `bg`/`text` strings can safely carry `dark:` variants.

**Primitives + screens.** `PromoStatusBadge` (full status-tint map) + `OverdueTag` + `VersionHistoryDrawer` migrated by hand; the 49 screen files migrated by **6 parallel agents** (one per folder group) driven by a shared cheat-sheet (hybrid rules: keep the light class, append `dark:`; brand `#FFD60A`/`bg-[#FFD60A]` → `primary` token; soft `bg-X-50 text-X-700` tints → `dark:bg-X-500/15 dark:text-X-300`; leave solid `-500` fills/dots/bars and already-adapting tokens). Data-level tint maps (`AUDIT_ACTION_META`, `NOTIFICATION_TYPE_META`, `PROMO_TYPE_RULE_STATUS_TINT`) in `promo-mock-data.ts` got dark variants too.

**Verified.** `build:promo` + `build:dashboard` both pass. Consistency greps found zero brand literals (besides one intentional `accent-[#FFD60A]` on a native radio), zero inline color styles, and zero unpaired light `bg-white`/`text-gray-*`/`bg-gray-*`/`border-gray-*` utilities. In-browser dark-mode walk (auth seeded) across **all 12 surface types** at 1920px + 390px: short calendar (Pattern-F), full calendar (Pattern-F editable, cancelled red-struck band, amber changed-cell, required markers, 1С banner, footer bar), reports (overdue/version badges, amber changed-cell ring, emerald added-row), audit (action chips, статус до→после), approvals (queue + Mode-B mobile cards), notifications, users (STATUS_META), profile (brand avatar/button keep dark on-yellow text), promo-types two-pane, and login (brand-yellow hero with preserved dark text + dark form panel).
