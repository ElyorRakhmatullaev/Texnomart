# Broker · Уточнение PM 18.08: ветка Alif — в попапе на «Выборе рассрочки»

> Дата: 2026-08-18 (вторая итерация дня) · Скоуп: `Broker/**` + документация.
> Источник: устное уточнение PM + скриншот попапа «Подтвердить выбор предложения?» (соответствует Figma-фрейму **32** секции «3-step: Choose BNPL», id `76:21611`: центрированный белый попап с затемнением фона поверх страницы банков, кнопки «Назад» / «Подтвердить», крестик закрытия).
> Предшественник: спека `2026-08-18-broker-alif-rework-tz-design.md` — её содержимое шагов (холд, доп. данные, OTP кредита, успех/договор) остаётся в силе; меняется **носитель**: не отдельные страницы-маршруты, а фазы одного попапа.

## 1. Требование PM

Все действия ветки Alif происходят **на странице «Выбор рассрочки»**: по «Оформить» у Alif Nasiya открывается попап с затемнением фона, и весь дальнейший процесс идёт в нём. Для других банков ничего не открывается (остаётся toast «В прототипе реализован сценарий Alif»). URL не меняется (`/scoring/banks`).

## 2. Решение

### 2.1. `AlifCheckoutDialog` — один Dialog, фазовая машина

Radix Dialog (затемнение — стандартный overlay), контент ~640px (фаза доп. данных — до 720px), крестик закрытия всегда доступен (кроме секунд «удержания» холда). Фазы:

| Фаза | Контент | Шаг степпера |
|---|---|---|
| `confirm` | «Подтвердить выбор предложения?» (по фрейму 32) + строка выбранного предложения (Alif Nasiya · N мес. · лимит · предоплата) + «Назад» (закрыть) / жёлтая «Подтвердить» | 3 |
| `hold` | контент нынешней `HoldPage` (сумма, карта списания, «Подтвердить удержание» → спиннер ~2 с → «Подтверждена» → «Продолжить»; «Отменить холд» → `holdCancel()` + закрытие попапа + toast). Фаза пропускается при `prepayment === 0` | 3 |
| `details` | контент нынешней `AdditionalDataPage` (доверительные лица + дата списания, та же валидация), «Продолжить» | 4 |
| `otp` | `OtpPanel variant="credit"` + сводка + амбер-callout (контент нынешнего `CreditOtpDialog`), CTA «Завершить» | 5 |
| `success` | зелёное состояние нынешней `InstallmentInfoPage` (галочка, «Кредит оформлен!», договор №, заявка 1С, «Скачать договор (PDF)», «Посмотреть договор», зелёная «Завершить скоринг» → `resetFlow()` + `/scoring/verification`) | 5 |

Переходы только вперёд + «Назад» на `confirm`; фаза **деривируется из состояния потока** (не хранится отдельно): `creditConfirmed` → `success`; `additionalData` → `otp`; `holdStatus === "confirmed"` или `prepayment === 0` (при `alifSelected`) → `details`; `alifSelected && подтверждён confirm` → `hold`. Для «подтверждён confirm» вводится новое поле `offerConfirmed: boolean`.

### 2.2. Состояние и маршруты

- `ScoringFlowState` += `offerConfirmed: boolean` и `checkoutOpen: boolean` (персистится: перезагрузка на открытом попапе → попап переоткрывается на дериватной фазе). «Оформить» (Alif) → `selectAlif(tenor)` + `openCheckout()`; закрытие × → `closeCheckout()` (прогресс в состоянии сохраняется; повторное «Оформить» продолжает с той же фазы). `holdCancel()` дополнительно сбрасывает `offerConfirmed`.
- **Маршруты `/scoring/alif/hold`, `/scoring/alif/details`, `/scoring/alif/info` удаляются** вместе со страницами `HoldPage`, `AdditionalDataPage`, `InstallmentInfoPage`, `CreditOtpDialog` (их контент переезжает в фазовые компоненты `checkout/*`); гварды `hold`/`details`/`info` удаляются из `RequireStage`. Остаются: `/`, `/scoring/verification`, `/scoring/myid`, `/scoring/banks`, `*`.
- Степпер: активный шаг = из pathname КАК СЕЙЧАС для шагов 1–3; при открытом попапе — из фазы (см. таблицу; передаётся через контекст потока, т.к. степпер живёт в `BrokerShell`). Шаги 4–5 достижимы только визуально (подсветка при фазах попапа) — отдельных страниц у них больше нет.
- «Завершить скоринг» после успеха (или из рейки) — единственный сброс; финализированное состояние (`creditConfirmed`) при закрытом попапе показывает на карточке Alif бейдж «Оформлена» и кнопку «Оформить» → попап на фазе `success` (повторный вход к договору).

### 2.3. Файлы

Новая папка `Broker/src/app/components/checkout/`: `AlifCheckoutDialog.tsx` (хост + фазовая машина + футер-навигация), `ConfirmPhase.tsx`, `HoldPhase.tsx`, `DetailsPhase.tsx`, `CreditOtpPhase.tsx`, `SuccessPhase.tsx` (контент переносится из удаляемых страниц с минимальной адаптацией: без контейнеров страниц, кнопки в футере фаз).

## 3. Вне скоупа / без изменений

Шаги 1–2 (верификация с карт-OTP-модалом, фото/MyID) не меняются. Мок-константы, `OtpPanel`, ошибки OTP — без изменений. Попапы «Отправить лимиты в Telegram» (фреймы 36/37) — не в этом скоупе.

## 4. Проверка

Build + браузерный QA: полный проход в попапе (confirm → hold → details → otp → success → скачивание PDF), отмена холда (закрытие + повторный вход с фазы confirm), закрытие × на каждой фазе + повторное «Оформить» (резюме фазы), перезагрузка с открытым попапом (переоткрытие на той же фазе), деп-линки на удалённые маршруты → redirect verification, степпер-подсветка фаз, Iman → toast, 390px (попап во всю ширину, Pattern E).
