# Promo · моушн-фильм для внешнего показа (покадровая запись)

> Дата: 2026-09-30 · Скоуп: `Promo/src/film/**` (новое), `Promo/scripts/record-film.mjs` (новое), `Promo/e2e/film.spec.ts` (новое), две точечные правки приложения (`main.tsx`, `routes.tsx`), `package.json` (корень + Promo), `.gitignore`, документация. Экраны Promo **не меняются**.
> Образец механики записи — присланный пользователем `record-tour.mjs` (headless Chrome по протоколу DevTools ставит каждый кадр на точный момент через `window.__capture.seek`, ffmpeg собирает видео).
> Дизайн согласован в разговоре 29–30.09 по трём частям: устройство, раскадровка и стиль, запись и проверка.

## 1. Что нужно

**Сказано пользователем:**
- Нужно моушн промо-видео продукта, собранное в стиле `record-tour.mjs`: без видеоредактора, покадрово, в MP4.
- Назначение — **внешний показ** (портфолио студии, соцсети): коротко, эффектно, меньше деталей интерфейса.
- Форматы — горизонтальный 16:9 и вертикальный 9:16.
- Подход — **гибрид**: живые экраны Promo + «героические» фрагменты из настоящих компонентов.

**Принятые допущения:**
- Продукт — Texnomart Promo (промо-календарь). Broker в этот фильм не входит.
- Сначала делается и согласуется 16:9, затем 9:16 из тех же сцен (§6).
- Длина 32 с, 60 кадров/с, монтаж по сетке 120 BPM.
- Язык титров — русский; узбекская версия (латиница) — тем же фильмом с `?lang=uz`. Интерфейс в кадре остаётся русским (в приложении нет runtime-i18n).
- Без диктора. Музыку пользователь подставляет при записи (`--audio`); права на трек — за ним.
- Название студии для финальной карточки неизвестно: константа `STUDIO_CREDIT` пустая, пока пользователь её не заполнит; при пустой строке карточка студии не показывается.
- Маршрут фильма попадает в деплой GitHub Pages — фильм можно открыть ссылкой `…/promo/embed/film` и смотреть в браузере (пользователь не возразил).

**Готово, когда:**
1. `corepack pnpm film:promo -- --lang ru` при запущенном dev-сервере Promo пишет `Promo/film-out/film-ru-16x9.mp4` — 1920×1080, 60 кадров/с, 32 с, H.264.
2. Один и тот же момент `t`, снятый дважды (с перемоткой между снимками), даёт одинаковый до пикселя кадр.
3. Ключевые кадры каждой сцены (`--stills`) просмотрены, в них нет обрезанного текста, пустых вложенных экранов и артефактов загрузки.
4. Обычная работа прототипа не изменилась: `build:promo` зелёный, `tsc` — 3 известные ошибки базовой линии, весь e2e-набор проходит.
5. Вторым этапом — то же для `--aspect 9x16` (1080×1920).

## 2. Границы

**Входит:** страница-фильм, режим кадра для вложенных экранов, восемь сцен (§4), скрипт записи, тесты, русская и узбекская версии титров, вертикальная раскладка (второй этап).

**Не входит:**
- Диктор, звуковые эффекты, подбор или генерация музыки.
- Мобильная вёрстка приложения в кадре — в 9:16 показывается настольный интерфейс крупным планом.
- Форматы 1:1 и 4:5.
- Размытие в движении (motion blur) — в разы замедляет рендер при малой пользе на интерфейсе.
- Фильм по Broker.
- Изменения экранов Promo ради фильма. Если сцене чего-то не хватает на экране, сцена меняется, а не экран.

### 3.2. Режим кадра (`frame-mode.ts`)

Включается только параметром `film-frame=1` в адресе вложенного экрана; без него модуль ничего не делает. Импортируется **первой строкой** `main.tsx`: порядок вычисления ES-модулей гарантирует, что подмены действуют раньше любого кода приложения.

Адрес вложенного экрана: `/<маршрут>?film-frame=1&role=<роль>&user=<id>&theme=light|dark`.

В режиме кадра:
- **Дата зафиксирована** на 28.09.2026 12:00 (Ташкент) — та же, что в e2e: `Date` подменяется подклассом, у которого `new Date()` без аргументов и `Date.now()` возвращают фиксированный момент; остальные конструкторы работают как обычно.
- **Хранилища в памяти.** `localStorage` и `sessionStorage` заменяются объектами в памяти с тем же API. `sessionStorage` засеивается входом: `auth = "true"`, `promo:current-user-id = <user>`, `promo:current-role = <роль>`; `localStorage` — `promo:pref-theme = <theme>`. Следствия: вложенные экраны не видят друг друга и не трогают сохранённое состояние прототипа во вкладке пользователя; перезагрузка экрана возвращает его в исходное состояние.
- **Анимации и переходы приложения выключены** стилем `*, *::before, *::after { animation: none !important; transition: none !important }`. Radix при отсутствии анимации монтирует и снимает всплывающие окна сразу, поэтому состояние экрана зависит только от выполненных действий, а не от времени.
- **Скрыты** полосы прокрутки и всплывающие уведомления sonner.

### 3.3. Модель времени (`timeline.ts`)

Чистые функции без зависимостей и без React (проверяется `node --test` без сборки). Только «стираемый» синтаксис TypeScript — без `enum`, `namespace` и параметров-свойств: Node 24 снимает типы сам, но такие конструкции не поддерживает.
- `Scene { key, duration, … }` → `buildTimeline(scenes)` даёт `{ duration, chapters: { key, at, end }[] }`.
- `sceneAt(timeline, t)` → сцена и локальное время внутри неё; `t` за концом ограничивается последним кадром.
- Плавности (`easeOutExpo`, `easeInOutCubic`, `easeOutBack`) и `keyframes(t, [{ at, value, ease }])` — интерполяция чисел и наборов чисел (камера, позиции, прозрачность).
- Сетка темпа: `beat(n)` = `n × 0.5 с`, `bar(n)` = `n × 2 с` — длительности в `scenes.ts` задаются через них.

### 3.4. Страница-фильм (`FilmPage.tsx`, маршрут `/embed/film`)

- Параметры: `capture=1` (режим записи), `lang=ru|uz` (по умолчанию `ru`), `aspect=16x9|9x16` (по умолчанию `16x9`).
- Холст — фиксированный размер в CSS-пикселях: 1920×1080 или 1080×1920. В режиме записи окно Chrome совпадает с холстом; в обычном браузере холст вписывается в окно масштабом с полями и фильм играет по `requestAnimationFrame` в цикле.
- Кадр — чистая функция от `t`: `sceneAt` выбирает сцену, сцена рисует себя по локальному времени. Видима одна сцена; следующая сцена-экран монтируется заранее скрытой (предзагрузка).
- Контракт записи — тот же, что в образце:
  ```ts
  window.__capture = {
    duration: number,                                   // секунды
    chapters: { key: string; at: number; end: number }[],
    seek(t: number): Promise<void>,
  }
  ```
  `seek(t)` выполняется, когда сцена момента `t` смонтирована, её вложенный экран (если есть) загружен, шрифты в нём готовы (`document.fonts.ready`), сигналы до `t` выполнены и прошло два кадра отрисовки.
- Код фильма загружается лениво (`lazy` у маршрута) и не попадает в основной бандл приложения.

### 3.5. Сцена «экран» (`ScreenScene.tsx`)

- Вложенное окно (`iframe`, тот же origin) с адресом режима кадра, вьюпорт **1440×900** — как у e2e и у скриншотов. Окно оформлено минимальной рамкой со скруглением и тенью, без адресной строки.
- **Камера** — `transform` контейнера окна (перенос, масштаб, наклон в перспективе), ключевые кадры в координатах холста, функция от локального времени сцены.
- **Сигналы** — действия с моментом времени: `click(селектор)`, `scroll(селектор, x, y)` (значение — функция от времени, для панорамы), `hover(селектор)`. `seek` выполняет сигналы в промежутке `(предыдущий t, новый t]`. При перемотке назад окно перезагружается (состояние в памяти обнуляется) и сигналы проигрываются заново до `t`.
- **Курсор** рисует фильм поверх окна (SVG, кольцо `#FFD60A` при клике). Точка курсора — центр элемента по селектору внутри окна, пересчитанный через текущую камеру.
- Не найден селектор сигнала → `seek` отклоняется с понятной ошибкой (имя сцены + селектор), запись останавливается. Молча пропускать нельзя — кадр был бы неверным.

### 3.6. Сцены «фрагменты» (`fragments/`)

Крупные элементы на тёмной сцене, собранные из **настоящих примитивов** Promo: `PromoStatusBadge` (и `PROMO_STATUS_CONFIG`), `Money`, `RuDate`, CSS-переменные темы. Каждая деталь анимируется отдельно функцией от времени. Выезжающие панели (`LineChangeDrawer` и т. п.) в фрагменты не берутся — они рендерятся порталом в корень документа; нужная композиция («Было → Стало») собирается из тех же примитивов. Логотип — тот же SVG, что в шапке приложения (`shell-config.tsx`).

## 4. Раскадровка и стиль (16:9)

120 BPM: удар = 0,5 с, такт = 2 с; смены сцен — на сильные доли. Ключи сцен = ключи глав для `--chapter`.

| # | Ключ | Время | Тип | Что в кадре | Титр RU (черновик) |
|---|---|---|---|---|---|
| 1 | `hook` | 0:00–0:03 | фрагмент | Три крупные фразы, каждая сменяет предыдущую на удар | «9 ролей.» · «Сотни позиций.» · «Каждая — через согласование.» |
| 2 | `logo` | 0:03–0:05 | фрагмент | Жёлтая линия прочерчивает кадр и собирается в логотип Texnomart Promo | — |
| 3 | `plan` | 0:05–0:11 | экран | Окно влетает с 3D-наклоном и выравнивается; краткий календарь (`/short-calendar`, «Коммерческий директор»), камера наезжает на план акций | «План акций на год — в одном окне» |
| 4 | `grid` | 0:11–0:15 | фрагмент | Строки кампаний (название, период, бейдж статуса) слетаются и защёлкиваются в сетку; бейджи загораются каскадом | — |
| 5 | `fullcal` | 0:15–0:21 | экран | Полный календарь (`/full-calendar`, «Категорийный менеджер (КМ)»): быстрая панорама по широкой таблице (цены, подарки, рассрочка) | «Каждая позиция: цена, подарки, рассрочка» |
| 6 | `change` | 0:21–0:25 | фрагмент | Карточка «Было → Стало»: старая цена зачёркивается, новая въезжает; бейдж «На согл. у КД» перетекает в «Согласовано КД» с пульсом галочки | «Любая правка — через согласование» |
| 7 | `audit` | 0:25–0:29 | экран | Аудит, вкладка сроков (`/audit`): чипы «В срок» и «Просрочка»; на сильной доле — клик по переключателю темы в шапке, экран уходит в тёмную тему | «Сроки под контролем» |
| 8 | `final` | 0:29–0:32 | фрагмент | Логотип + «Промо-календарь для сети Texnomart»; ниже — карточка студии (если `STUDIO_CREDIT` задан) | «Дизайн и прототип — ‹STUDIO_CREDIT›» |

Точные вкладки, строки и селекторы для сцен 3, 5, 7 выбираются в плане по живым экранам; значения в чипах и бейджах на экранах — те, что показывает прототип на зафиксированную дату (фильм их не подделывает). Узбекские титры — черновой перевод, требует проверки носителем.

**Стиль:**
- Сцена почти чёрная `#0E0E10`; титры белые, Inter 700, 120–160 px, плотный трекинг; подписи сцен 3–6 слов, внизу слева.
- Светлые окна продукта парят на тёмной сцене с мягкой тенью.
- `#FFD60A` — только акцент: линии, кольцо курсора, рамки подсветки, тонкие полосы переходов. Большими заливками жёлтый не используется (правило дизайн-системы).
- Входы — с резким торможением (`easeOutExpo`), камера — `easeInOutCubic`; 60 кадров/с.
- Цвета в коде — точные hex через `style={{}}`, как требует `.claude/rules/design.md`.

## 5. Запись (`scripts/record-film.mjs`)

Перенос образца со следующими изменениями:
- **Chrome:** `CHROME` или стандартные пути macOS/Linux **и Windows** (`C:\Program Files\Google\Chrome\Application\chrome.exe`, `Program Files (x86)`, `%LOCALAPPDATA%`).
- **ffmpeg:** `FFMPEG` или PATH; если не найден — ошибка с подсказкой `winget install Gyan.FFmpeg`. Установка в систему — отдельным шагом с согласия пользователя.
- **Адрес:** `{base}/embed/film?capture=1&lang=<lang>&aspect=<aspect>`; `--base` по умолчанию `http://localhost:5173` (dev-сервер Promo), работает и с деплоем GitHub Pages (`…/Texnomart/promo`).
- **Часовой пояс** `Asia/Tashkent` через `Emulation.setTimezoneOverride`.
- `--page tour|film` → `--aspect 16x9|9x16` (1920×1080 или 1080×1920); `--theme` убран (темы задаёт сценарий).
- **Сохраняются:** `--lang`, `--chapter`, `--stills`, `--audio` (обрезка по картинке, затухание 2 с), `--4k` (тот же холст, масштаб 2), `--codec h264|hevc|prores`, `--crf`, `--fps` (по умолчанию 60), цветовая разметка BT.709, повторная отрисовка кадра при перезагрузке dev-сервера, PNG без потерь до кодека.
- **Вывод** по умолчанию — `Promo/film-out/film-<lang>-<aspect>[-<chapter>][-4k].mp4` (`.mov` для ProRes); кадры `--stills` — туда же.
- Запуск: `corepack pnpm film:promo -- --lang ru`. Оценка времени: 1920 кадров ≈ 3–5 мин на 1080p, в 2–3 раза дольше на 4K.

## 6. Вертикальная версия 9:16 (второй этап)

- Те же сцены, шкала времени и трек; меняется только раскладка — у каждой сцены вариант под соотношение сторон (`aspect` приходит в сцену параметром).
- В сценах-экранах вьюпорт остаётся 1440×900; камера выбирает вертикальный участок и показывает его крупнее.
- Титры переносятся в 2–3 строки; фрагменты перестраиваются столбиком.
- Запись: `--aspect 9x16`.

## 7. Проверка

- **`scripts/film-timeline.test.ts`** (`node --test`, Node 24 сам снимает типы): длительность и главы из списка сцен; `sceneAt` на границах сцен и за концом; `keyframes` на ключах и между ними; плавности на 0 и 1.
- **`e2e/film.spec.ts`** (Playwright, существующий конфиг):
  - `__capture` отдаёт `duration` = 32 и восемь глав с ключами из §4;
  - детерминизм: снимок на момент внутри каждой сцены-экрана (`plan`, `fullcal`, `audit`), затем перемотка вперёд и назад, повторный снимок — совпадают побайтно;
  - режим кадра: вложенный экран не пишет в `localStorage`/`sessionStorage` основной вкладки; `Date.now()` в нём равен зафиксированному моменту;
  - без `film-frame` приложение ведёт себя как прежде (существующий набор остаётся зелёным).
- **Визуально:** `--stills` на входе, середине и выходе каждой сцены; кадры смотрю как изображения. Весь ролик в движении проверяет пользователь по MP4.
- **Без регрессий:** `build:promo` зелёный; `tsc` из scratchpad — 3 известные ошибки; весь e2e-набор проходит.

## 8. Риски

- **Загрузка вложенных экранов.** Следующий экран предзагружается, `seek` ждёт загрузки и шрифтов — медленнее запись, кадры не страдают.
- **Подмена `Date` и хранилищ** — только при `film-frame=1`; изоляцию проверяет e2e.
- **Перемотка назад** перезагружает экран — дорого, но запись идёт только вперёд; назад перематывают лишь `--stills` (на 2 с) и тест.
- **Селекторы сигналов** привязаны к разметке экранов: при будущих правках экранов сцена может сломаться — это видно сразу, `seek` падает с именем сцены и селектором (§3.5).
- **3D-наклон с iframe в headless Chrome** — проверяется первым же кадром сцены `plan`; при артефактах наклон заменяется плоским влётом с масштабом.
