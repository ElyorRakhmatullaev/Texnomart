## 1. Задача

Сегодня распределение существует только как сид: `PromoCampaign.categoryDistribution` заполняется в `promo-mock-data.ts`, а в интерфейсе его негде создать или изменить. Клиент просит, чтобы **коммерческий директор** мог — необязательно, по мере необходимости — распределить промо по КМ, дням и категориям, а КМ увидел, что распределение появилось.

## 2. Архитектурное решение

### 2.1. Хранение — отдельный стор + чистое слияние на посеве

Новый **`Promo/src/lib/distribution-store.ts`**:

```ts
/** Сериализуемая запись (Date → ISO-строка date-only). */
interface StoredEntry { date: string; category: string; responsibleKmId: string; }

/** localStorage `promo:category-distribution`: id акции → записи. */
export function getDistributionMap(): Record<string, StoredEntry[]>;
export function getDistributionFor(campaignId: string): CategoryDistributionEntry[] | undefined;
export function setDistributionFor(campaignId: string, entries: CategoryDistributionEntry[]): void;
export function clearDistributionFor(campaignId: string): void;

/**
 * Чистое слияние: сохранённое распределение перекрывает сид целиком
 * (запись по акции — это полный список, а не патч).
 * Акции без записи остаются как есть.
 */
export function applyDistribution(campaigns: PromoCampaign[]): PromoCampaign[];
```

Оба потребителя (краткий календарь и экспорт из него) применяют `applyDistribution` **в момент посева** — тот же приём, что `applyLineDecisions` в Волне 3: общий факт → persist + чистая свёртка на входе каждого потребителя, без подъёма состояния в провайдер. `CategoryDistributionEntry` не меняется, поэтому блок, фильтры и экспорт продолжают работать как есть.

Пустой массив — валидное значение и означает «распределения нет»; `clearDistributionFor` удаляет ключ, возвращая акцию к сиду. Это два разных намерения, и их нельзя схлопывать: «очистить введённое» ≠ «вернуть сид».

### 2.2. Действие в «Плане акций»

`PlanApprovalTable` — в колонке «Действия» появляется кнопка **«Распределить»** (иконка `Users`), колонка расширяется 240 → 300px.

Видимость: `canDistribute = (роль «Коммерческий директор» || активное уполномоченное лицо КД) && строка не черновик`. Уполномоченное лицо определяется существующим `canActAsKd` (E-4) — своей логики не заводим.

Черновики исключены осознанно: распределять ещё нечего, а кнопка без смысла — это «нажимаю, ничего не происходит» из клиентских отчётов.

Кнопка — обычная, не пункт Radix-меню: меню под shared `<Button>` рендерится за экраном (уроки Волны 1, три подтверждённых клиентских бага).

### 2.3. Форма — Dialog (Pattern E)

Открывается **отложенно** (`setTimeout(…, 0)`): контролируемый Dialog, открываемый обычной кнопкой, самозакрывается — тот же клик ловится DismissableLayer как outside-interaction (урок S2 Phase 3, рецидив в `PlanMode`).

Состав:
- Шапка — «26-N · Название · период ДД.ММ.ГГГГ — ДД.ММ.ГГГГ».
- Список строк распределения, каждая:
  - **Дата** — `Select` по дням периода акции, подпись «пн · 02.11.2026» (это и есть «автоматическое подтягивание дат из периода», стр. 73 п. 5);
  - **Категория** — поле ввода с подсказками (`datalist`) из категорий `CATEGORY_MANAGERS` и номенклатуры; свободный ввод разрешён («категория указывается вручную», стр. 74 п. 4);
  - **Ответственный КМ** — `Select` по `CATEGORY_MANAGERS`;
  - удаление строки.
- «+ Добавить строку» — новая строка с первой датой периода, категорией и КМ по умолчанию пустыми.
- «Очистить распределение» — удаляет все строки (возврат к общей логике, стр. 74 п. 6).
- «Сохранить» — пишет в стор.

Валидация: все три поля обязательны; дата внутри периода (гарантировано выбором из списка); пара «дата + категория» не повторяется. Кнопка сохранения заблокирована с текстом ошибки, как в форме пользователя 5D.

### 2.4. Индикатор для КМ

Рядом с плашкой-переключателем «Распределение по категориям» в `CalendarFilters` — зелёный **пульсирующий** кружок, когда одновременно: блок свёрнут, активная роль «Категорийный менеджер (КМ)», и среди видимых акций есть хотя бы одна с распределением. Раскрытие блока снимает индикатор само по себе, поэтому состояние «просмотрено» хранить не нужно.

Пульсация — под `motion-safe:` (`motion-safe:animate-pulse`): буквально мигающий элемент нарушает доступность, а клиент дал формулировку «например, зелёный мигающий/пульсирующий кружок» — то есть способ привлечь внимание, а не точное требование к анимации.

Индикатор висит на общем переключателе, а не на строках: пока блок свёрнут, per-row плашек не существует.

### 2.5. Аудит

Сохранение распределения пишет одно событие существующего типа **«изменение»** по объекту **«план»** с `changes[]` вида «Распределение по категориям: 0 → 3 позиции» (поле `changes` появилось в 5D). Обоснование: распределение — действие КД по плану, а живые действия КД по плану пишутся в аудит с Волны 4; отдельный тип действия не нужен.

## 3. Что НЕ входит (YAGNI)

- Распределение **не становится этапом согласования** и не блокирует продвижение плана — оно необязательное (стр. 74 п. 5).
- Полный календарь, S3 и уведомления не трогаем.
- Справочник категорий как сущность не заводим — подсказки берутся из существующих данных.
- Модель `CategoryDistributionEntry` не меняется (иначе поехали бы блок, фильтры и экспорт).
- Распределение не меняет видимость акций для КМ: «по умолчанию промо доступно всем КМ» уже выполняется, распределение только подсказывает ответственных.

---

## 4. Риски

| Риск | Снятие |
|---|---|
| Слияние сида и стора разъедется между календарём и экспортом | Единственная точка — `applyDistribution` на посеве; экспорт строится из тех же строк, что таблица (как в Волне 4 с `plan-approval.ts`). |
| Кнопка включена там, где действие бессмысленно | `canDistribute` и поведение вводятся одной задачей — аффорданс и его смысл не разъезжаются во времени (урок Волны 4). |
| Диалог самозакрывается при открытии | Отложенное открытие + проверка **настоящим** кликом, а не `element.click()`. |
| Транспайл-онли сборка не заметит рассинхрона типов | После каждой задачи — открытие экрана в браузере. |
| Индикатор мигает у ролей, которым он не адресован | Условие включает активную роль КМ; проверяется переключением ролей. |
