> Дата: 2026-09-28 · Скоуп: `Promo/**` (тесты, конфиг, скрипты) + корневой `package.json` + документация. Код приложения **не меняется**.
> Источник требований: жёлтые строки листа «PROMO_CALENDAR (Проверка прод.)» (№12–27, выгрузка `PROMO_CALENDAR_Проверка_прод_жёлтые_строки_№12-27.md`) и чек-лист-артефакт «Сверка прототипа Promo» (шаги и роли по каждому пункту + пять доработок 25.09).
> Фактическое поведение сверено с кодом четырьмя исследованиями 28.09 (вход и пользователи · полный календарь и согласование · краткий календарь, план, распределение · отчёты, уведомления, аудит). Строки интерфейса ниже взяты из исходников.

## 1. Что нужно

**Сказано пользователем:** полноценные Playwright-тесты по выполненным задачам №12–27; «протестируйте различные сценарии».

**Принятые допущения:**
- Тестируется **прототип** (этот репозиторий, деплой GitHub Pages), не прод `promo.tm.uz`.
- «Различные сценарии» — по каждому пункту не только основной путь, но и негативные случаи, различия по ролям и доступу, сохранение после перезагрузки и граничные случаи.
- Тест проверяет **требование**, а не текущее поведение. Если прототип требованию не соответствует, тест не подгоняется: он помечается как известный дефект (§5), дефект идёт в отчёт пользователю, правка прототипа — отдельным шагом с его согласия.

**Готово, когда:**
1. Одна команда поднимает прототип и прогоняет весь набор; все тесты проходят, известные дефекты отмечены как ожидаемо падающие.
2. Три прогона подряд дают одинаковый результат (нет плавающих тестов).
3. Тот же набор без правок запускается против GitHub Pages переменной `BASE_URL`.
4. Код приложения не изменён.

### 3.3. Фикстура `app`

- **Вход без формы.** Признак входа, пользователь и роль живут в sessionStorage вкладки (`auth`, `promo:current-user-id`, `promo:current-role`). `test.use({ user: 'u-2', role: 'Администратор' })` кладёт их через `addInitScript` **только если ключей ещё нет**, чтобы перезагрузка страницы не сбрасывала роль, выбранную в тесте. Форму входа проверяют отдельные тесты `auth.spec.ts`.
- **Смена роли — только через меню аватара** (кнопка с инициалами → пункт с названием роли), без перезагрузки. Новые строки, отправки и правки в полном календаре живут в памяти страницы: перезагрузка стёрла бы их, и сценарий «КМ добавил черновик → КД его не видит» стал бы непроверяемым.
- **Реальные входы там, где важна личность.** «Вам как: <роль>» у Администратора не показывается никогда (проверка по собственным ролям пользователя), поэтому №17 идёт под реальными пользователями: u-4 (КМ), u-5 (ст. КМ), u-1 (КД), u-6 (сотрудник маркетинга). u-8 для роли КМ не используется: он — активное «Уполномоченное лицо КД» и видит интерфейс КД.
- **Переходы по относительному пути** (`app.open('reports?promo=UN-2026-015')` без ведущего `/`), иначе при `baseURL` c `/Texnomart/promo/` адрес уйдёт в корень сайта.
- **Скачивания:** `app.download(действие)` ловит событие, возвращает имя и содержимое; CSV разбирается с учётом BOM, `;` и экранирования `"=""26-1"""`; XLSX читается уже подключённым `xlsx`.
- **Уведомления-тосты:** проверка текста через `app.toast(текст)`; sonner держит их 5 с справа сверху, поэтому после тоста, закрывающего шапку, меню аватара открывается после его исчезновения или закрытия.

### 3.4. Время и данные

- Сиды частично считаются от «сейчас»: SLA очереди, возраст уведомлений («Сегодня», «N мин назад»), рейтинг участников (задача входит, когда её дедлайн наступил), окна временных ролей и замещения (u-6 — ДМ в августе, истекло; u-8 — замещение КД до 31.12.2026), имена файлов выгрузок. Фиксированное время 28.09.2026 12:00 держит их стабильными.
- `setFixedTime`, а не `clock.install`: вход ждёт `setTimeout` 600 мс, таймеры должны идти.
- Тест, которому нужно другое время (истечение замещения, блокировка входа на 15 минут), ставит его сам.
- Изоляция: у каждого теста свой контекст с пустыми localStorage и sessionStorage; сиды пишутся приложением при первом чтении. Тест, проверяющий сохранение, делает `page.reload()` внутри себя.

### 3.5. Поиск элементов

- По ролям и русским подписям (`getByRole`, `getByLabel`, `getByText`), как видит пользователь. `data-testid` в коде нет и не добавляется.
- **Двойной DOM.** Таблицы по образцу F — две синхронные панели: название строки и иконки в закреплённой (`.group/row`), остальные ячейки — в прокручиваемой; название акции и «26-3» повторяются в каждой строке, названия товаров встречаются и в ячейках подарков. Строки ищутся по названию внутри закреплённой панели. Краткий календарь рендерит таблицу и мобильные карточки одновременно — локаторы ограничиваются `table` или видимыми элементами. Кнопки решений в карточке согласования есть дважды (панель `lg:` и мобильная полоса).
- Числа форматируются с неразрывным пробелом: сравнение по регулярному выражению (`/4\s440\s000 сум/`).
- Латинская «c» в «c 15.06.2026 по 31.12.2026» панели замещения — строка сравнивается как есть.

## 7. Риски

- **Хрупкие тексты.** Тесты завязаны на русские подписи: переименование кнопки ломает тест. Это осознанный выбор — подпись и есть требование клиента; `data-testid` не добавляем, чтобы не менять код приложения.

- **Время прогона.** 124 теста параллельно на локальном Vite — ориентировочно 3–4 минуты (`playwright.config.ts` капает `workers: 4` — см. `tasks/lessons.md` 2026-09-28: дефолтные 8 воркеров держат CPU на 97–100% и изредка роняют 30с таймаут в календарном пикере).
