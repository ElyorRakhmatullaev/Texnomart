## 1. Пять пунктов ТЗ → решения в моке

### 1.1. 🔴 Фото клиента (критично)
Alif требует `extra.myid_photo` обязательным; текущий MyID Redirect фото не отдаёт → нужен захват фото **внутри приложения**. В моке: шаг «Проверка MyID» (step 2) становится экраном **фото + проверка** по паттерну Figma-фрейма 11 (заголовок, чипы-подсказки «Держите положение лица» / «Не закрывайте лицо» / «Хорошее освещение», область камеры) с добавлением **овальной рамки** (по ТЗ: анфас, лицо полностью в овале):
- Камера через `getUserMedia` (video → canvas → JPEG blob). Нет камеры/отказ в доступе → плашка «Камера недоступна» + кнопка «Использовать демо-фото» (сгенерированный нейтральный силуэт-аватар из ассетов мока, гарантированно проходящий проверку; НЕ фото реального человека).
- Проверка по ТЗ: формат png/jpg/jpeg, размер **300 КБ – 1,5 МБ**, без предварительной обрезки/сжатия. Мок проверяет реальный размер blob'а; вне диапазона → состояние ошибки «Фото не соответствует требованиям (…)» + «Переснять». Съёмка ведётся в разрешении/качестве, обычно попадающем в диапазон.
- Состояния: превью → «Использовать фото» → «Проверка MyID…» (мок ~2,5 с, спиннер) → «Личность подтверждена» → «Продолжить». «Вернуться к предыдущему шагу» → верификация.
- ⚠️ ТЗ: требования могут измениться после ответа Alif/MyID — мок строится по текущим; отметка в `Broker/CLAUDE.md`.

### 1.2. 🟡 OTP привязки карты → модал на шаге верификации
Новый шаг 1 «Верификация клиента» (Figma 8–10): слева «Данные клиента» (Номер телефона / Серия и номер паспорта / ПИНФЛ — предзаполнены сидом), справа «Данные карты»: список привязанных карт (сид: одна карта `9860 3569 7266 1296 · 11/29`, бейдж «Подтверждена»), поля «Номер карты» + «Срок карты», зелёная плашка «Чем больше карт, тем выше шанс получить нужный лимит» + зелёная «Добавить», у строк — иконка удаления. «Добавить» → **модал** «Подтверждение карты»: «Введите код из SMS, отправленного на карту •••• XXXX», OTP 6 цифр, resend с таймером, ошибки:
- `000000` → «Неверный код. Проверьте SMS и попробуйте ещё раз»;
- номер карты, оканчивающийся на `0000` → ошибка ещё до OTP: «Карта не найдена»;
- оканчивающийся на `9999` → «Лимит исчерпан на привязку. Карта заблокирована для привязки» (модал с ошибкой, без поля OTP).
Успех → карта в списке со статусом «Подтверждена», toast. «Продолжить» активна при ≥1 подтверждённой карте.

### 1.3. 🟡 Холд предоплаты
Сид Alif получает `prepayment: 1_000_000` (ТЗ: поле «всегда 0» — проблема; карточка банка начинает показывать реальную предоплату). После «Оформить» у Alif, если `prepayment > 0` → новый под-экран **`/scoring/alif/hold`** (степпер остаётся на «Выбор рассрочки»):
- Карточка: «Предоплата по рассрочке» — сумма 1 000 000 сум, карта списания (первая подтверждённая, «9860 •••• 1296»), пояснение «Средства будут удержаны (холд) и списаны после оформления кредита».
- Кнопка «Подтвердить удержание» → статус-индикатор: «Предоплата удерживается…» (мок ~2 с, спиннер) → бейдж «Предоплата подтверждена» + «Продолжить» (→ доп. данные).
- «Отменить холд» доступна до финализации: статус «Отменена», возврат на «Выбор рассрочки» (holdStatus сбрасывается).
- Если `prepayment === 0` (другие банки/сценарии) — шаг пропускается, переход сразу к доп. данным.

### 1.4. 🟡 OTP подтверждения кредита → модал на финальном экране
Финальный экран **`/scoring/alif/info`** «Информация по рассрочке» (структура 41/42, двухпанельная):
- Слева — карточка рассрочки (как сейчас: Alif, срок из `state.tenor`, лимит, предоплата — теперь 1 000 000 + строка статуса холда).
- Справа — панель завершения. **Состояние A (до подтверждения):** нейтральная панель «Проверьте условия и завершите оформление» + кнопка «Завершить скоринг» → **модал** «Подтверждение кредита» (зелёный чип «Подтверждение кредита», сводка: сумма/срок/предоплата, амбер-callout «Это другой код — не тот, что при привязке карты», OTP + resend; `000000` → ошибка). Успех → **Состояние B (зелёное):** галочка, «Кредит оформлен!», договор №, «Заявка №235662235 в базе 1С создана…», кнопки «Скачать договор (PDF)» + «Посмотреть договор» + зелёная «Завершить скоринг» (сброс → верификация).

### 1.5. 🟢 Просмотр/скачивание договора
В зелёном состоянии: «Скачать договор (PDF)» (как сейчас, `download="Договор_<№>.pdf"`) + «Посмотреть договор» — открытие `contract-mock.pdf` в новой вкладке (`target="_blank" rel="noopener"`). Отдельный previewer не строим (ТЗ допускает «просто ссылку»).

## 2. Архитектура переработки

### 2.1. Маршруты и гварды (v2)

| Маршрут | Шаг степпера | Гвард |
|---|---|---|
| `/` → redirect `/scoring/verification` | — | — |
| `/scoring/verification` | 1 «Верификация клиента» | — |
| `/scoring/myid` | 2 «Проверка MyID» | ≥1 подтверждённая карта |
| `/scoring/banks` | 3 «Выбор рассрочки» | `myidDone` |
| `/scoring/alif/hold` | 3 | `alifSelected && prepayment > 0` |
| `/scoring/alif/details` | 4 «Дополнительные данные» | `alifSelected` && (prepayment=0 или `holdStatus="confirmed"`) |
| `/scoring/alif/info` | 5 «Информация по рассрочке» | `additionalData` заполнены |
| удаляются | `/scoring/alif/card`, `/scoring/alif/confirm` | — |

Степпер: единый массив 5 шагов (ALIF_STEPS и ветвление удаляются), активный шаг из pathname, кламп сохраняется.

### 2.2. Состояние (v2, sessionStorage `broker:scoring-flow` — формат меняется, старые блобы совместимы через `{...INITIAL, ...parsed}`; устаревшие поля игнорируются)

```ts
interface AttachedCard { mask: string; expiry: string; confirmed: boolean }
interface ScoringFlowState {
  cards: AttachedCard[]            // сид: одна подтверждённая
  photoDone: boolean               // фото прошло проверку
  myidDone: boolean                // проверка MyID завершена
  alifLimitStatus: "pending" | "ready"
  alifSelected: boolean
  tenor?: number
  holdStatus: "none" | "held" | "confirmed" | "cancelled"
  additionalData?: AdditionalData
  creditConfirmed: boolean
  contractNo?: string
  oneCOrderNo?: string
}
```
`cardAttached` удаляется (заменён `cards[].confirmed`). Экшены: `addCard(mask, expiry)`, `confirmCard(mask)`, `removeCard(mask)`, `setPhotoDone()`, `setMyidDone()`, `holdConfirm()/holdCancel()`, остальные прежние. `resetFlow` → верификация (карты возвращаются к сиду).

### 2.3. Компоненты
- **`OtpPanel`** (рефакторинг `OtpStepCard`): чип-вариант, subtitle, children, OTP+resend+ошибки, CTA — без карточки-обёртки и без «Вернуться…». `OtpStepCard` удаляется вместе с экранами; хосты: `CardOtpDialog` (шаг 1), `CreditOtpDialog` (шаг 5) — shadcn Dialog ≤ 480px, на мобильном Sheet не требуется (Pattern E допускает компактный Dialog для OTP).
- **`VerificationPage`**, **`MyIdPhotoPage`** (+`useCameraCapture` хук: getUserMedia/фолбэк/снимок/размер), **`HoldPage`**, **`InstallmentInfoPage`** (замена SuccessPage) — новые Broker-локальные.
- Мок-данные: + `SEED_CARD`, `CARD_ERROR_SUFFIXES`, `PREPAYMENT_HOLD_DELAY_MS = 2000`, `MYID_CHECK_DELAY_MS = 2500`, `PHOTO_MIN_BYTES = 300_000`, `PHOTO_MAX_BYTES = 1_500_000`; Alif `prepayment: 1_000_000`.

### 2.4. Краевые случаи
Перезагрузка на любом шаге — восстановление по состоянию; прямой заход — редирект по гвардам к первому незакрытому шагу; «Завершить скоринг» из рейки — сброс на верификацию; отмена холда возвращает к банкам без потери tenor; модалы открываются обычными кнопками (не Button-asChild — репо-готча); повторное открытие карт-модала после «карта заблокирована» — с чистым состоянием.

## 3. Вне скоупа
Логин/PIN (до шага 1), реальный MyID/ML-проверка лица, previewer PDF внутри приложения, ветки других банков, интеграция реальных API, «Подбор товара», тёмная тема. Требования к фото могут поменяться после ответа Alif/MyID — при изменении корректируется только `MyIdPhotoPage`.
